# Split Prediction Table Schemas

This page documents the current split prediction and accuracy table layouts
used by the active pipeline and website. The architecture separates live
next-show predictions from retained completed-show history.

## Live Next-Show Prediction Tables

### `next_show_prediction_runs`

Canonical live next-show storage. Contains one active run per
`(band, model_slug, model_version, target_show_key)`. Older live rows are
deleted once the target is no longer the next known show.

```sql
CREATE TABLE public.next_show_prediction_runs (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamptz NOT NULL DEFAULT now(),
    band text NOT NULL,
    model_slug text NOT NULL,
    model_version text NOT NULL,
    target_show_key text NOT NULL,
    target_show_date date NOT NULL,
    reference_date date NOT NULL,
    generated_at timestamptz NOT NULL,
    top_k integer NOT NULL,
    predictions jsonb NOT NULL,
    CONSTRAINT next_show_prediction_runs_pkey PRIMARY KEY (id),
    CONSTRAINT next_show_prediction_runs_context_key
        UNIQUE (band, model_slug, model_version, target_show_key),
    CONSTRAINT next_show_prediction_runs_top_k_positive CHECK (top_k > 0)
);
```

### `next_show_prediction_songs`

Derived per-song projection for SQL-friendly website reads. Rebuildable from
`next_show_prediction_runs`. Cascade-deletes when the parent run is deleted.

```sql
CREATE TABLE public.next_show_prediction_songs (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamptz NOT NULL DEFAULT now(),
    prediction_run_id bigint,
    band text NOT NULL,
    model_slug text NOT NULL,
    model_version text NOT NULL,
    target_show_key text NOT NULL,
    target_show_date date NOT NULL,
    reference_date date NOT NULL,
    generated_at timestamptz NOT NULL,
    rank integer NOT NULL,
    song_name text NOT NULL,
    top_k integer NOT NULL,
    prediction_payload jsonb NOT NULL,
    CONSTRAINT next_show_prediction_songs_pkey PRIMARY KEY (id),
    CONSTRAINT next_show_prediction_songs_run_fkey
        FOREIGN KEY (prediction_run_id)
        REFERENCES public.next_show_prediction_runs (id)
        ON DELETE CASCADE,
    CONSTRAINT next_show_prediction_songs_context_rank_key
        UNIQUE (band, model_slug, model_version, target_show_key, rank),
    CONSTRAINT next_show_prediction_songs_rank_positive CHECK (rank > 0),
    CONSTRAINT next_show_prediction_songs_top_k_positive CHECK (top_k > 0)
);
```

Notes:

- `prediction_run_id` links each song row to the parent run; cascade deletes
  keep the projection consistent.
- `prediction_payload` stores the exact model-specific JSON object for that
  ranked song.

## Retained Completed-Show Tables

### `completed_show_prediction_runs`

Canonical retained completed-show snapshots. Stores the exact ranked boards
for the active last-50 completed-show corpus per band/model. Rows outside
the retained corpus are hard-deleted by the sync script.

```sql
CREATE TABLE public.completed_show_prediction_runs (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamptz NOT NULL DEFAULT now(),
    band text NOT NULL,
    model_slug text NOT NULL,
    model_version text NOT NULL,
    target_show_key text NOT NULL,
    target_show_date date NOT NULL,
    reference_date date NOT NULL,
    generated_at timestamptz NOT NULL,
    actual_songs jsonb NOT NULL,
    actual_song_count integer NOT NULL,
    top_k integer NOT NULL,
    predictions jsonb NOT NULL,
    CONSTRAINT completed_show_prediction_runs_pkey PRIMARY KEY (id),
    CONSTRAINT completed_show_prediction_runs_context_key
        UNIQUE (band, model_slug, model_version, target_show_key),
    CONSTRAINT completed_show_prediction_runs_actual_song_count_positive
        CHECK (actual_song_count > 0),
    CONSTRAINT completed_show_prediction_runs_top_k_positive CHECK (top_k > 0)
);
```

Notes:

- This is the canonical lineage store for scored historical prediction boards.
- `predictions` preserves the exact ranked JSON payload emitted by the model.
- `actual_songs` preserves the setlist snapshot used when the row was scored.

### `completed_show_accuracy`

Canonical per-show evaluation store. One row per retained evaluated completed
show and model version. Links back to `completed_show_prediction_runs` via
`prediction_run_id`.

```sql
CREATE TABLE public.completed_show_accuracy (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamptz NOT NULL DEFAULT now(),
    band text NOT NULL,
    model_slug text NOT NULL,
    model_version text NOT NULL,
    show_id text NOT NULL,
    target_show_key text NOT NULL,
    show_date date NOT NULL,
    target_show_date date NOT NULL,
    reference_date date NOT NULL,
    prediction_run_id bigint,
    actual_song_count integer NOT NULL,
    evaluated_at timestamptz NOT NULL,
    k10_hit integer NOT NULL,
    k10_matches integer NOT NULL,
    k10_precision double precision NOT NULL,
    k10_recall double precision NOT NULL,
    k10_f1 double precision NOT NULL,
    k25_hit integer NOT NULL,
    k25_matches integer NOT NULL,
    k25_precision double precision NOT NULL,
    k25_recall double precision NOT NULL,
    k25_f1 double precision NOT NULL,
    k50_hit integer NOT NULL,
    k50_matches integer NOT NULL,
    k50_precision double precision NOT NULL,
    k50_recall double precision NOT NULL,
    k50_f1 double precision NOT NULL,
    CONSTRAINT completed_show_accuracy_pkey PRIMARY KEY (id),
    CONSTRAINT completed_show_accuracy_run_fkey
        FOREIGN KEY (prediction_run_id)
        REFERENCES public.completed_show_prediction_runs (id)
        ON DELETE CASCADE,
    CONSTRAINT completed_show_accuracy_context_key
        UNIQUE (band, model_slug, model_version, target_show_key)
);
```

Notes:

- The `k10_*`, `k25_*`, `k50_*` metric families each contain `hit`,
  `matches`, `precision`, `recall`, and `f1`.
- `prediction_run_id` links each evaluation row to the exact stored ranked
  board that produced it.
- This is the only active evaluation source for historical performance
  analysis.

## Row-Level Security

All four tables have RLS enabled with:

- `anon` role: `SELECT` (public read)
- `service_role` role: `ALL` (pipeline writes)

## Legacy Tables

The following legacy tables remain in the database for backward compatibility
during the migration period, but are not the active website-facing source of
truth:

- `predictions` — legacy unified prediction table
- `prediction_songs` — legacy derived per-song projection
- `historical_prediction_runs` — legacy scored-run lineage
- `accuracy_per_show` — legacy per-show accuracy (uses `model_version` instead
  of `model_slug`)

Per-model tables (`predictions_notebook`, `predictions_deal`, `predictions_ckplus`,
`notebook_accuracy`, `accuracy_ckplus`, `accuracy_deal`) have been dropped by
migration `20260415`.

See `docs/reference/specifications/predictions_schema.md` for the full migration
status and current canonical table descriptions.
