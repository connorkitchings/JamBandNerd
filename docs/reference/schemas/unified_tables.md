# Unified Table Schemas

This page documents the current shared prediction and accuracy table layouts
used by the active pipeline. These schemas reflect the current implementation,
not speculative future storage designs.

## Prediction Tables

Current prediction tables:

- `predictions_notebook`
- `predictions_ckplus`
- `prediction_songs` (derived)

Both use the same table layout.

```sql
CREATE TABLE public.predictions_notebook (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamp with time zone NOT NULL DEFAULT now(),
    band text NULL,
    reference_date date NULL,
    predictions jsonb NULL,
    top_k integer NULL,
    model_version text NULL,
    predicted_at timestamp with time zone NULL,
    CONSTRAINT predictions_notebook_pkey PRIMARY KEY (id),
    CONSTRAINT predictions_notebook_band_reference_date_model_version_key
        UNIQUE (band, reference_date, model_version)
);
```

`predictions_ckplus` uses the same column layout with table and constraint names
adjusted accordingly.

Notes:

- `predictions` is a ranked JSON array.
- JSON entry fields differ by model.
- the current design stores one row per `(band, reference_date, model_version)`
  as the canonical write boundary.

### Per-Song Prediction Projection

```sql
CREATE TABLE public.prediction_songs (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamp with time zone NOT NULL DEFAULT now(),
    band text NOT NULL,
    model_slug text NOT NULL,
    model_version text NOT NULL,
    reference_date date NOT NULL,
    predicted_at timestamp with time zone NOT NULL,
    rank integer NOT NULL,
    song_name text NOT NULL,
    top_k integer NOT NULL,
    prediction_payload jsonb NOT NULL,
    CONSTRAINT prediction_songs_pkey PRIMARY KEY (id),
    CONSTRAINT prediction_songs_band_model_version_reference_date_rank_key
        UNIQUE (band, model_version, reference_date, rank)
);
```

Notes:

- `prediction_songs` is derived from `predictions_{model}`, not written as an
  independent source of truth.
- `prediction_payload` stores the exact model-specific JSON object for that
  ranked song.

## Aggregate Accuracy Tables

Current aggregate accuracy tables:

- `notebook_accuracy`
- `accuracy_ckplus`

Both use the same metric layout.

```sql
CREATE TABLE public.notebook_accuracy (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamp with time zone NOT NULL DEFAULT now(),
    band text NULL,
    model_version text NULL,
    window_start date NULL,
    window_end date NULL,
    num_shows integer NULL,
    evaluated_at timestamp with time zone NULL,
    k10_hit_rate double precision NULL,
    k10_avg_matches double precision NULL,
    k10_precision double precision NULL,
    k10_recall double precision NULL,
    k10_f1 double precision NULL,
    k25_hit_rate double precision NULL,
    k25_avg_matches double precision NULL,
    k25_precision double precision NULL,
    k25_recall double precision NULL,
    k25_f1 double precision NULL,
    k50_hit_rate double precision NULL,
    k50_avg_matches double precision NULL,
    k50_precision double precision NULL,
    k50_recall double precision NULL,
    k50_f1 double precision NULL,
    CONSTRAINT notebook_accuracy_pkey PRIMARY KEY (id),
    CONSTRAINT notebook_accuracy_band_model_version_window_start_window_end_key
        UNIQUE (band, model_version, window_start, window_end)
);
```

`accuracy_ckplus` uses the same column layout with table and constraint names
adjusted accordingly.

## Per-Show Accuracy Table

```sql
CREATE TABLE public.accuracy_per_show (
    id bigint NOT NULL GENERATED BY DEFAULT AS IDENTITY,
    created_at timestamp with time zone NOT NULL DEFAULT now(),
    band text NOT NULL,
    model_version text NOT NULL,
    show_id text NOT NULL,
    show_date date NOT NULL,
    actual_song_count integer NOT NULL,
    k10_hit integer NULL,
    k10_matches integer NULL,
    k10_precision double precision NULL,
    k10_recall double precision NULL,
    k10_f1 double precision NULL,
    k25_hit integer NULL,
    k25_matches integer NULL,
    k25_precision double precision NULL,
    k25_recall double precision NULL,
    k25_f1 double precision NULL,
    k50_hit integer NULL,
    k50_matches integer NULL,
    k50_precision double precision NULL,
    k50_recall double precision NULL,
    k50_f1 double precision NULL,
    evaluated_at timestamp with time zone NOT NULL,
    CONSTRAINT accuracy_per_show_pkey PRIMARY KEY (id),
    CONSTRAINT accuracy_per_show_band_model_version_show_id_key
        UNIQUE (band, model_version, show_id)
);
```

Notes:

- `accuracy_per_show` is the canonical historical evaluation store.
- aggregate accuracy tables are derived summaries over windows of these rows.
