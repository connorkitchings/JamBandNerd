# Dev Log: Goose Supabase Migration

**Date:** 2025-07-24

---

## Summary

Migrated Goose data collection and prediction pipelines to use Supabase for storage, following the
Phish model pattern. All raw data is loaded in-session from the Goose API; only prediction results
are stored in Supabase. Two prediction tables (`goose_predictions_ckplus` and
`goose_predictions_notebook`) were created in Supabase, matching the Phish schema. The CK+ model
pipeline was fully migrated and tested; the Notebook model pipeline was updated to fix JSON
serialization errors for datetime columns and now saves predictions to Supabase successfully.

---

## Key Actions & Decisions

- **Supabase Table Creation:**
  - Created `goose_predictions_ckplus` and `goose_predictions_notebook` in Supabase, matching Phish
    schema (see `CREATE_GOOSE_PREDICTION_TABLES.sql`).
- **Pipeline Refactor:**
  - Updated both Goose prediction pipelines to load all raw data from the Goose API at runtime,
  - Process in memory, and store only predictions in Supabase.
  - Ensured no persistent raw data tables for Goose exist in Supabase (Phish pattern).
- **Datetime Serialization Fix:**
  - Fixed JSON serialization errors in the Notebook pipeline by converting all datetime/Timestamp
    columns to ISO string format before saving to Supabase.
  - Improved error logging for Supabase save failures.
- **Testing:**
  - CK+ prediction pipeline tested end-to-end; predictions saved to Supabase.
  - Notebook prediction pipeline tested after serialization fix; predictions now save successfully.
- **Documentation:**
  - Updated onboarding and dev logs to reflect migration steps, design decisions, and testing
    outcomes.

---

## Blockers & Resolutions

- **Blocker:** JSON serialization error in Notebook pipeline when saving Timestamp objects to Supabase.
  - **Resolution:** Applied robust conversion of all datetime columns to ISO strings before upsert;
    verified fix with end-to-end test.

---

## Next Steps

- Monitor Supabase for successful prediction saves after future runs.
- Continue to follow Phish pattern for any future band migrations.
- Document any further schema or pipeline changes in this log.
