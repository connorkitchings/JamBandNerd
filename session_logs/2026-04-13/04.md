# Session Log — 2026-04-13 / 04

## Goal

Implement a supported-model freshness escalation path so degraded WSP runs no longer look healthy while Notebook or Deal data ages out past the allowed reuse window.

## Constraints

- Keep the change band-agnostic in code even though WSP degraded-mode reuse is the immediate driver.
- Preserve existing prediction and accuracy validators for the normal regeneration path.
- Do not fail the workflow before per-band status artifacts and summary output are written.

## Changes

- Added `scripts/check_supported_model_freshness.py`.
  - Reads the supported model set from the registry.
  - Audits latest prediction rows for models enabled for pipeline or web.
  - Audits latest per-show and aggregate accuracy rows for models enabled for accuracy validation.
  - Emits GitHub Actions outputs:
    - `freshness_state`
    - `stale_prediction_models`
    - `stale_accuracy_models`
    - `max_prediction_age_hours`
    - `max_accuracy_age_hours`
    - `freshness_reason`
  - Uses a `48h` threshold by default.
  - Treats missing supported-model rows as stale.
  - Downgrades stale accuracy to `warning` when `--skip-accuracy` is passed.

- Updated `.github/workflows/daily-pipeline.yml`.
  - Runs the new freshness audit under `always()` whenever the band was operationally active for the run.
  - Writes freshness fields into the per-band JSON status artifact.
  - Appends freshness details to the per-band GitHub summary.
  - Adds a final enforcement step after artifact upload and summary append.
  - Fails degraded runs when supported-model predictions exceed the `48h` reuse window.
  - Fails non-degraded runs when supported-model predictions or required accuracy remain stale.
  - Does not fail manual `skip_accuracy=true` runs solely because supported accuracy remained stale.
  - Updates the pipeline-summary header to call out stale supported-model freshness separately from generic degraded state.

- Updated `scripts/generate_pipeline_summary.py`.
  - Added a `Supported Model Freshness` section.
  - Surfaces freshness state, stale supported models, max prediction age, max accuracy age, degraded-data reuse, and freshness notes per band.

- Updated documentation and CI surfaces:
  - `docs/operations/github_actions.md`
  - `docs/overview/implementation_status.md`
  - `scripts/README.md`
  - `.github/workflows/repo-quality.yml`

- Added regression coverage:
  - `tests/test_check_supported_model_freshness.py`
  - extended `tests/test_generate_pipeline_summary.py`

## Outcome

JamBandNerd now has an explicit stale-freshness escalation path for supported models. Degraded collection can still reuse recent outputs temporarily, but supported prediction freshness is no longer allowed to drift past `48h` without turning the band job red and leaving evidence in the workflow artifacts and summary.
