# Session Log — 2026-04-12 / 03

## Goal

Investigate and fix the apparent mismatch between:

1. `scripts/generate_predictions.py` for Goose Notebook at `reference_date=2026-04-11`
2. `scripts/run_backtest.py` / replay rows shown from `historical_prediction_runs`

## Constraints

- Keep replay backed by `historical_prediction_runs`; do not paper over a semantic mismatch by swapping tables.
- Preserve the `reference_date` anti-leakage boundary.
- Avoid schema changes.

## Root Cause Identified

The ranking mismatch was caused by comparing two different prediction semantics:

- Live predictions are keyed directly by the requested `reference_date`
- Replay/backtest rows are keyed by `target_show_date`, and the stored prediction cutoff is the prior calendar day via `get_evaluation_reference_date(target_show_date)`

For Goose:

- `generate_predictions.py --band goose --model notebook --date 2026-04-11`
  - uses `reference_date=2026-04-11`
  - top 10 begins with `Silver Rising, SALT, Dripfield, Tumble, ...`
- replay row for completed show `2026-04-11`
  - uses `reference_date=2026-04-10`
  - top 10 begins with `Dustin Hoffman, Rockdale, SALT, Tumble, ...`

Confirmed with direct local reproduction against current raw tables:

- direct Notebook prediction at `2026-04-11` matches `predictions_notebook` / `prediction_songs`
- direct Notebook prediction at `2026-04-10` matches `historical_prediction_runs` for `target_show_date=2026-04-11`

## Additional Fix

Found and fixed an unrelated but real API bug in shared feature generation:

- `generate_model_data()` previously overrode any caller-provided `exclusion_window` whenever `band` was passed
- this meant script CLI flags and experiment overrides were silently ignored
- now explicit caller values win, and band/default config is only used when the caller omits the value
