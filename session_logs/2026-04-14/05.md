# Session Log — 2026-04-14 / 05

## Goal

Investigate why WSP Deal predictions on the site showed `Little By Little`
with `current_gap = 4` while the current next-show snapshot should not include
that song.

## Findings

- The underlying WSP Notebook/Deal feature math for the current next-show target
  (`reference_date = 2026-04-17`) was consistent with the raw play history:
  `Little By Little` last appeared on `2026-03-21`, so Notebook correctly
  excludes it from the recent-show window and the current Deal next-show board
  also does not include it.
- The website bug was in snapshot selection, not in Deal's feature generation.
- `apps/web/src/lib/data.ts` seeded live snapshot selection from
  `prediction_songs` by reading up to 100 rows ordered by `predicted_at`, but
  each prediction snapshot contributes ~50 rows.
- For WSP Deal, two newer historical snapshots (`2026-02-15` and `2026-03-22`)
  consumed the 100-row limit before the future `2026-04-17` snapshot could be
  considered, so the site selected the wrong board.

## Changes Made

- Updated `apps/web/src/lib/data.ts` so the live seed query filters to
  `rank = 1` rows before applying the limit.
- Added an inline comment explaining that the limit must apply to snapshots
  rather than arbitrary song rows within a snapshot.
