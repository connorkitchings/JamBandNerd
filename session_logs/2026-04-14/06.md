# Session Log — 2026-04-14 / 06

## Goal

Redefine `current_gap` so it means "completed shows since the song was last
played," then update WSP live prediction rows so the website reflects that
definition immediately.

## Findings

- The existing implementation used `reference_index - last_played_index`, which
  implicitly counted the target show itself.
- Under that definition, a song last played on the immediately previous
  completed show displayed as `current_gap = 1`; the desired meaning is `0`.
- The user's WSP example was correct:
  - `Little By Little` last played `2026-03-21`
  - one completed show occurred after that on `2026-03-22`
  - so the correct `current_gap` for the `2026-04-17` target is `1`
- Notebook exclusion logic based on `recently_played_songs` was already aligned
  with "last N completed shows"; the off-by-one was in the serialized gap
  feature itself.

## Changes Made

- Updated Notebook current-gap calculation in
  `src/jambandnerd/models/notebook/model.py` to:
  - `reference_index - last_played_index - 1`
  - clipped at `0`
- Updated Deal current-gap calculation in
  `src/jambandnerd/models/deal/features.py` to the same definition.
- Adjusted Deal candidate filtering from `current_gap > 1` to
  `current_gap > 0` so the feature semantics and exclusion behavior stay
  aligned.
- Added tests covering the new gap definition in:
  - `tests/models/test_notebook_model.py`
  - `tests/models/test_deal_model.py`
- Refreshed WSP live `prediction_songs` projections directly for:
  - Notebook (`reference_date = 2026-04-17`)
  - Deal (`reference_date = 2026-04-17`)
  This was done directly against `prediction_songs` because the connected live
  database still lacks the unified `predictions` table expected by the current
  canonical writer.
