# Billy Strings source migration: bmfsdb.com → billybase.net

## Goal

Fix the failing `Daily Pipeline - billy` job by switching the Billy Strings data source from `bmfsdb.com` (returning HTTP 500 for 2+ days) to `billybase.net`, while preserving the existing prediction corpus keyed on `show_id`.

## Constraints

- `billy_shows_raw.source_uuid` is `uuid not null unique` and the upsert conflict column; `show_id` is the foreign key for setlists, predictions, and accuracy tables.
- The historical corpus used bmfsdb UUIDs; BillyBase uses human-readable slugs, so slug-derived UUIDs would duplicate existing rows without reconciliation.
- No degraded-mode workflow changes (user explicitly chose "just the source switch").
- BillyBase is server-rendered WordPress/Elementor, so the existing Livewire/Playwright fallback for bmfsdb's upcoming view is no longer needed.
